# Support and contributions

Report reproducible problems in the repository's GitHub Issues. Include app version, operating system/version, CPU architecture, installation type, interface language, and steps to reproduce. For Linux include X11 or Wayland. Describe expected and observed behavior. Remove personal information from screenshots and logs; never attach backups, notes, app keys, signing credentials, or a database.

For content-access failures, confirm an internet connection and retry. Unavailable translations may reflect the registered application's licenses. Missing online Scripture does not imply lost local notes. Export a backup before reinstalling or changing versions.

Contributors should run frontend checks and Rust tests, preserve provider attribution and license boundaries, and test the desktop behavior affected by a change. Use GitHub private vulnerability reporting when enabled for security issues; do not publish exploit details or secrets in a public issue. If private reporting is not enabled, request a private reporting channel without disclosing the vulnerability.

## Trying an alpha

Download only the installer matching your operating system and CPU from the GitHub prerelease assets. Read that release’s build and verification status: alpha availability does not establish runtime support. Unsigned macOS and Windows builds may be blocked or show publisher warnings; follow your organization’s security policy. Alpha builds update manually and have no stable automatic-update feed. Export a personal-data backup before installing a newer version, and include the exact alpha tag when reporting a problem.
